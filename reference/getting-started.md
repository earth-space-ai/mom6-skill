# Getting Started with MOM6

This guide takes you from zero to a built ocean-only MOM6 executable that
passes the regression suite. After this, see `running-experiments.md` to
launch a real ocean simulation, or `coupling.md` for coupled builds.

---

## Step 1: Understand the two-repo layout

Unlike single-repo land-surface models, MOM6 is split across two GitHub
repos that you almost always need together.

| Repo | What it is | URL |
|------|-----------|-----|
| `NOAA-GFDL/MOM6` | The source code (`src/`, `config_src/`, `pkg/`, `ac/`, `docs/`, `.testing/`) | https://github.com/NOAA-GFDL/MOM6 |
| `NOAA-GFDL/MOM6-examples` | Experiment configurations, regression data, build templates, the user wiki | https://github.com/NOAA-GFDL/MOM6-examples |

The `.testing/` subdirectory inside `MOM6` is the smallest, fastest test
suite. The full MOM6-examples repository ships much larger benchmarks
(double_gyre, OM4_025 quarter-degree global, ocean_SIS2, NeverWorld2, ...)
and is the right place to learn experiment layouts. The MOM6-examples wiki
is the canonical install guide for every supported HPC platform.

Branches in `NOAA-GFDL/MOM6`:

- **`main`**: stable. The default branch.
- **`dev/gfdl`**: GFDL's active development branch. Pull requests target this.
- Tags: `release-yyyy.NN` for periodic releases.

## Step 2: Clone with submodules

```bash
git clone --recurse-submodules https://github.com/NOAA-GFDL/MOM6
cd MOM6
ls
# expects: ac/  config_src/  docs/  LICENSE.md  pkg/  README.md  src/  .testing/
ls pkg
# expects: CVMix-src  GSW-Fortran
```

`pkg/CVMix-src` and `pkg/GSW-Fortran` are vendored as git submodules.
`src/parameterizations/CVmix` is a symlink into `pkg/CVMix-src/src/shared`,
and `src/equation_of_state/TEOS10` links into `pkg/GSW-Fortran`. The build
will fail to link without them.

If you forgot `--recurse-submodules`:

```bash
git submodule update --init --recursive
```

## Step 3: Install prerequisites

### Fortran + C compilers

A modern compiler with Fortran 2003/2008 support:

- **gfortran** (GCC 9+ recommended; 11+ for fewer warnings)
- **Intel ifort** or **ifx**
- **NVIDIA nvfortran** (works for MOM6 itself; some FMS components are picky)
- **Cray ftn** on Cray HPCs

The companion C compiler must be from the same family. On NCAR Derecho /
Casper, use `gfortran` + `gcc` or `ifx` + `icx` from the same module.

### MPI

OpenMPI, MPICH, Intel MPI, or Cray MPICH. The autoconf path tries to
auto-detect the MPI Fortran wrapper (`mpifort`, `mpif90`, `ftn`), but you can
force it with `MPIFC=...`.

### netCDF (C and Fortran)

The Fortran bindings (`netcdf-fortran`) are a separate package from the C
library (`netcdf-c`).

- **macOS:** `brew install netcdf netcdf-fortran open-mpi`
- **Ubuntu / Debian:** `sudo apt-get install libnetcdf-dev libnetcdff-dev openmpi-bin libopenmpi-dev`
- **NCAR Derecho / Casper:** `module load netcdf openmpi` (the exact module
  names depend on the compiler stack you load first)
- **TACC Stampede3 / Frontera:** `module load netcdf` after the compiler module

Use `nc-config --includedir` and `nf-config --flibs` if `configure` fails to
find netCDF.

### Autoconf and Automake

`ac/configure` is generated by `autoreconf` and is not committed.

- **macOS:** `brew install autoconf automake`
- **Linux:** `sudo apt-get install autoconf automake`

### Python (for `ac/makedep` and helper scripts)

Python 3.6+. No third-party packages required for the core build.

## Step 4: Build the FMS dependency

MOM6 cannot run without GFDL's Flexible Modeling System. The autoconf path
provides a helper that fetches and builds a pinned FMS into `ac/deps`:

```bash
cd ac/deps
make -j
```

This downloads `mkmf` (build-rule generator) and FMS at the commits
specified by `MKMF_COMMIT` and `FMS_COMMIT` in `ac/Makefile.in`, then
compiles them. If you already have an external FMS install you want to
target, set `PATH`, `FCFLAGS`, and `LDFLAGS` so that the configure step
finds them, and skip this `make`.

## Step 5: Generate `configure` and build the ocean-only executable

```bash
cd ../..                       # back to MOM6/
cd ac
autoreconf                     # produces ac/configure
cd ..

mkdir -p build && cd build
../ac/configure                # picks up FC, MPIFC, netCDF, FMS
make -j                        # builds the MOM6 executable in build/
```

The result is a `MOM6` binary in `build/`. This is the **ocean-only**
executable: `config_src/drivers/solo_driver/`. It cannot run coupled.

Useful `configure` flags (full list with `../ac/configure --help`):

| Flag | Effect |
|------|--------|
| `--enable-asymmetric` | Use nonsymmetric grid memory layout (default is symmetric) |
| `--enable-openmp` | Enable OpenMP parallelism alongside MPI |
| `--disable-real-8` | Compile with single-precision reals. Not supported for production |
| `FC=ifx CC=icx FCFLAGS='-O2 -g'` | Override compiler and flags |
| `MKMF_URL=...` `FMS_COMMIT=...` | Pin a different mkmf or FMS source |

For a debug build, append `-g -O0 -fbacktrace -ffpe-trap=invalid,zero,overflow -fcheck=bounds`
to `FCFLAGS` (gfortran), or `-g -O0 -traceback -fpe0 -check all` (Intel).
See `debugging.md`.

## Step 6: Smoke test against `.testing/`

```bash
cd ../.testing
make -j                        # builds .testing/build/{symmetric,asymmetric,...}/MOM6
make -j test                   # runs tc0..tc4 with several transformations
```

`make -j test` runs the full transformation suite (grid, layout, restart,
repro, dim, nan) on tc0..tc4. A clean run looks like:

```
PASS  tc1.symmetric.grid
PASS  tc1.symmetric.layout
PASS  tc1.symmetric.restart
PASS  tc2.symmetric.grid
...
```

Individual groups can be run via `make -j test.grid`, `make -j test.layout`,
`make -j test.restart`, `make -j test.repro`, `make -j test.dim`, or
`make -j test.nan`. To enable the regression test that checks against a
target branch:

```bash
make -j DO_REGRESSION_TESTS=true MOM_TARGET_LOCAL_BRANCH=dev/gfdl test.regression
```

For unit tests:

```bash
make -j build.unit
make -j run.unit
```

See `.testing/README.rst` for the full configuration matrix.

## Step 7: Run a real experiment

The `.testing` cases are intentionally tiny. For real ocean experiments use
**MOM6-examples**:

```bash
git clone --recurse-submodules https://github.com/NOAA-GFDL/MOM6-examples
cd MOM6-examples
ls ocean_only            # double_gyre, benchmark, NeverWorld, OM4, ...
ls ice_ocean_SIS2        # ocean + sea-ice configurations
```

Building the MOM6-examples cases uses the GFDL `mkmf` workflow rather than
autoconf. Detailed step-by-step instructions live on the
[MOM6-examples wiki](https://github.com/NOAA-GFDL/MOM6-examples/wiki).
Workflow basics are in `running-experiments.md`.

## Common install pitfalls

| Symptom | Cause | Fix |
|---------|-------|-----|
| `pkg/` empty after clone | Forgot `--recurse-submodules` | `git submodule update --init --recursive` |
| `cannot find -lnetcdff` | Fortran netCDF bindings missing | Install `netcdf-fortran` separately from `netcdf-c` |
| `Could not find FMS` at configure | FMS not built and not on `LDFLAGS` | `make -C ac/deps`, or set `LDFLAGS=-L/path/to/fms/lib` |
| `autoreconf: command not found` | autoconf missing | `brew install autoconf automake` or apt equivalent |
| `Symbol not found: __netcdf_*` at link | netCDF built with one compiler, MOM6 with another | Rebuild netCDF with matching compiler, or `module load` matched stack |
| `mpif90: command not found` | MPI not in `PATH` | `module load openmpi` or set `MPIFC=...` |
| `tc1.symmetric.repro` fails | Aggressive optimization breaks bit reproducibility | Lower `FCFLAGS_REPRO` to `-O2` or unset `DO_REPRO_TESTS` |

For platform-specific gotchas, see the
[MOM6-examples wiki "Getting Started"](https://github.com/NOAA-GFDL/MOM6-examples/wiki/Getting-started)
and the GitHub Discussions on `NOAA-GFDL/MOM6`.
